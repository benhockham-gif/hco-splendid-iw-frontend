**Changed:** `product.html`, `category.html`, `assets/site.css` (new "v4.5" blocks at the end). `site.js` is unchanged.

These rules come from a review of all 81 fields across the full catalogue (30,079 products), tested on 21 real products from 10 categories. The sample values in the templates are for layout only.

## How rows disappear

Every new row is wrapped in `data-iw-product-has="<key>"`, the same as `has="pack"` today. **Remove the wrapper when the value is empty, null or 0.** Never show "0", "true" or an empty label.

## 1. Product page: top of the page (`.pdp-title`)

Order: brand, then range link, then name, then code. The range link has moved **above** the name. Its slots are unchanged (`data-iw-range-link`, `data-iw-product-range`, still pending `range-link`).

## 2. Description and key points

| Part | Slot | Rule |
|---|---|---|
| Description | `<div data-iw-product-description>` (was a `<p>`) | Split the text on line breaks. On each line, remove a leading `•`, `-` or `*` and the spaces after it. If the first line had no bullet, write it as a `<p>`. Write the remaining lines as `<ul class="desc-list"><li>`. A one-line description is just a `<p>`. |
| Key points | `<ul data-iw-product-keypoints>` › `<li data-iw-keypoint>` › `data-iw-keypoint-text`, wrapper `has="keypoints"` | One row per filled `key_point_1`–`key_point_6`, in order. Keep the tick SVG as it is. (`key_point_7`–`11` are always empty.) |

## 3. Buy box

| Part | Slot | Rule |
|---|---|---|
| Pack breakdown | `has="pack-spec"` › `data-iw-product-pack-spec` (inside the pack box, under "Sold in packs of") | From `pack_spec`, only when there's an inner box ("24 boxes of 250"). Leave it out when `pack_spec` just repeats the pack ("Box of 24"). |
| 18+ notice | `has="age-restricted"`, keys `product.age.title`, `product.age.text` | Only when `offensive_item` is true (39 products). Splendid to confirm the wording. |

**Price each is the price of one item, always** (`data-iw-product-unit-price`, product page and cards):
- Under £1: pence, up to 2 decimals ("1.25p"). £1 and over: £ with 2 decimals.
- Number in the pack = outer × inner ("24 Boxes of 250" = 6,000), so the pack box reads "Sold in packs of 6,000" and the card reads "£75.12 per pack of 6,000".
- 70 products (69 Steelite) currently send a box price as `price_each`. See the transformer fix in section 8.

## 6. Variant table (under the buy box)

`<div data-iw-pending="variants" data-iw-product-variants>`. Show it only when the product has other sizes. Each row is `<tr data-iw-variant-item>` and holds:
- `data-iw-variant-link` / `-label`: a link to that product
- `data-iw-variant-code`
- `data-iw-variant-pack`
- `data-iw-variant-price`: price each, using the section 3 rule
- `<form data-iw-variant-add method="post">` with a hidden `product` input and `quantity`. Each row adds its own product.

On the current row, put `aria-current="true"` on the `<tr>`, write the label without a link, and show the "Viewing" tag. Sort rows small to large. The column heading `data-iw-variant-axis` holds "Size" (or "Colour"…).

**Colour row** (when a range comes in colours too; see `splendid-review/variant-picker-colour.html`): `data-iw-variant-group` › `-axis`, `-current`, items with `-image` (the product photo), `-label`, and `aria-current` on the current colour. A colour that doesn't come in the current size gets `data-iw-variant-unavailable` and a `-sub` "28.5cl only", and links to its nearest size. The CSS for this row is in the review file and will move into `site.css` when colour families exist.

New keys: `variants.heading` Sizes in this range · `variants.viewing` Viewing · `variants.add` Add.

## 7. Category filters

The facet slots are unchanged. Order: **Brand, Range, Type, Style, Material, Colour, Size, Capacity, Care and features, Price (each, ex VAT)**. That's the Specification order, with Brand and Range first and Price last.
- Show up to 6 options, sorted by count. The rest go in `<details class="more" data-iw-facet-more>` › summary `category.filter.showall` "Show all" + `data-iw-facet-total`.
- Leave out a filter with no options in the current category.
- Size uses the key size (section 8). Price uses `price_each` only.
- The old sample filters (Glass style, Availability, Supplier) are removed.

## 8. Fixes needed in the transformer (engineering)

1. **Zero means empty:** turn 0 into null for every quantity and measurement field (pack, pallet, outers per layer, sales box size and weight, dimensions, weight, capacity).
2. **Values only in the name:** one parser that fills empty fields from the name, converts units (litres → cl, kW → W, cm ↔ in) and logs what it couldn't read. Cases:
   - size: 5,203 products
   - capacity: 2,782 products
   - power: 10 products (new `power_w`)
   - clothing size and colour
3. **Key size:** store one searchable, filterable size per product (`size_cm` + `size_in`), taken from the right measurement for the type: diameter for plates, bowls and saucers; length for straws and stirrers. The products team will confirm the other types.
4. **Box price sent as "each":** where `pack_spec` is "N Boxes of M" and N = `pack_size` (or "1 Box of M" with pack 1), work out units = N × M and price each = `price_per_pack` ÷ units. Affects 70 products.
5. **Variant families:** there's no field linking sizes of one item. Add `family_id` + `axis` (size / colour). Our inferred grouping is brand + range + name with the size removed: 1,672 families, 5,926 products.
6. **Category mapping:** a ladle and scoops are in uniform-clothing, and appliance parts are in appliances. Find whether the cause is the feed, the mapping or the import.
7. **Brand "WALCO HW/BUFFET":** check the feed against the import.
